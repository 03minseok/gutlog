## 프론트엔드 작업 규칙
- 백엔드 API와 필드 이름을 정확히 맞춘다. (예: 백엔드가 `eatenAt`이면 프론트도 `eatenAt`)
- 컴포넌트는 기능(도메인)별 폴더로 구성한다.
- API 호출은 공통 클라이언트(axios)를 통하며, 개별 화면에 흩뿌리지 않는다.
- 개발 서버에서는 `/api` 요청을 `http://localhost:8080`으로 프록시한다.
- 무엇을 만들기 전에 API 명세(`/v3/api-docs`), 루트 CLAUDE.md의 동작 규칙, 관련 디자인 시안을 먼저 확인한다.
- 입력 검증(길이, 허용 문자, 범위)은 API 명세의 검증 조건과 똑같이 맞춘다.
- 저장·수정·삭제 버튼은 요청을 보낸 뒤 응답이 올 때까지 비활성화한다. (중복 요청 방지)
- 삭제 전에는 확인창을 띄운다.
- API가 없는 기능에 가짜 데이터를 하드코딩하지 않는다. 비워두거나 개발자에게 묻는다.

### 인증 처리
- 로그인 응답의 `accessToken`을 저장한다.
- **요청 인터셉터**: 모든 요청에 `Authorization: Bearer {accessToken}` 헤더를 자동으로 붙인다.
- **응답 인터셉터**: 401을 받으면 저장된 토큰을 지우고 로그인 화면으로 보낸다.
  - 단, 로그인 요청(`/api/users/login`)의 401은 제외한다. 비밀번호 오류이므로 폼에 문구만 표시한다.
- 로그인이 필요한 화면은 토큰이 없으면 로그인 화면으로 보낸다. (화면 흐름 제어용이며, 실제 보안은 백엔드가 담당)

### 로그인 화면
- 카카오·네이버 로그인, 아이디·비밀번호 찾기는 **아직 API가 없다. 화면에 표시하지 않는다.**

### 회원가입 화면
- 회원 유형(환자/보호자/기타)을 먼저 고른다.
- 환자를 골랐을 때만 질환 종류 선택을 보여준다. 4개 타일을 2열 그리드로 배치한다.
- 아이디 옆 "중복 확인" 버튼은 아이디 중복 확인 API를 사용한다.
- 약관 동의
  - 체크박스 UI만 만든다. 필수 항목을 모두 체크해야 가입 버튼이 활성화된다.
  - 동의 내역을 저장하는 API는 **아직 없다. 서버에 보내지 않는다.**
- 가입 성공 후 같은 아이디·비밀번호로 로그인 API를 호출해 바로 홈으로 이동한다.

### 식사 기록 화면
- 음식은 여러 개 입력할 수 있다. 입력 중 콤마(또는 엔터)로 구분해 **칩(태그) 형태**로 보여준다.
- 음식 자동완성: 화면 진입 시 내 음식 목록을 한 번 받아, 입력한 글자가 포함된 음식을 프론트에서 걸러 보여준다. 글자를 칠 때마다 서버에 요청하지 않는다.
- 한글 입력 조합 중의 엔터는 칩 추가로 처리하지 않는다.
- 식사를 저장·수정한 뒤에는 내 음식 목록을 다시 받는다.

### 배변 기록 화면
- 배변 시각의 기본값은 지금 시각이며 수정할 수 있다.
- 혈변 여부는 "있음 / 없음" 중 **사용자가 직접 고른다. 기본값을 미리 선택해두지 않는다.** 고르지 않으면 저장할 수 없다.
- 배변 형태는 브리스톨 1~7형을 위 표시 이름으로 보여주고 하나를 고른다.
- 통증은 **0~5**로 기록하고, 새 기록의 기본값은 **0**이다. (2026-10-13 개발자 결정. 백엔드 검증은 0~10 그대로라 그 안의 값만 보낸다)
- 메모는 선택이며, 남은 글자 수를 보여준다.
- 혈변이 있는 기록은 목록과 홈 요약에서 눈에 띄게 표시한다.

## 디자인
- 디자인 기준: `docs/design/README.md` (v2, 모노 + 하늘). 모든 화면은 이 문서의 토큰과 컴포넌트 규칙으로 만든다.
- 토큰은 `frontend/src/index.css`의 `@theme`에 있다. 정해진 색·글자 크기(8단계)·radius 토큰만 쓰고, 임의값(`text-[15px]`, `#hex` 등)을 새로 만들지 않는다.
- 새 화면은 기존 공통 컴포넌트(`frontend/src/components/`)를 먼저 쓰고, 새 패턴이 필요하면 README에 규칙을 추가한다.
- 빨강(`blood`)은 혈변 전용이다. 오류는 `error`(황토색), 삭제는 아이콘 + 확인창으로 구분한다.
- v1 시안(`docs/design/archive/`)은 보관용이다. 색·크기 값은 따르지 않고, 통계 화면의 구성·데이터 규칙만 참고한다.
- 디자인 문서와 API가 다른 경우(예: 선택지 개수, 입력 규칙) **API를 기준**으로 하고, 다른 점을 개발자에게 알린다.
