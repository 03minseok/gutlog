# backend/CLAUDE.md

공통 규칙(API 계약, 브랜치·커밋, 완료 전 확인)은 루트 CLAUDE.md 참고.

## ⚠️ 역할 분담 — 반드시 지킬 것

### 백엔드 (`backend/src/main`)
- 개발자가 설계(ERD, API 명세, 핵심 판단)를 정하고, Claude가 구현한다.
- Claude는 구현 전에 계획을 먼저 보여주고 확인을 받는다.
- 설계가 정해지지 않은 판단(삭제 방식, 유니크 조건, 초기 데이터 등)은 임의로 정하지 말고 개발자에게 묻는다.
- 기존 코드의 패턴(소유권 검사 404, 기간 조회 >= / <, 요청 DTO 검증, 공통 응답)을 따른다.

### 백엔드 테스트 (`backend/src/test`) — Claude가 작성
- 테스트 코드는 Claude가 작성한다.
- 테스트가 실패하면 **`src/main` 코드를 고쳐서 통과시키지 않는다.** 실패 원인만 보고한다.
- 각 테스트는 서로 영향 없이 독립적으로 실행되게 만든다.

## 완료 전 확인
`backend/`에서 실행한다.
- `./gradlew test` — 컴파일 + 테스트
- 결과가 `UP-TO-DATE`면 코드가 바뀌지 않아 이전 실행에서 통과한 결과를 그대로 쓴다는 뜻이다. 강제로 다시 돌릴 때는 `./gradlew test --rerun`
